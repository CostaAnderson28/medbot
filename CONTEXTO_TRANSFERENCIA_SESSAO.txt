1) RESUMO EXECUTIVO
================================================================
- Projeto: chatbot multi-tenant para Instagram DM com painel web,
  API Express e SQLite (better-sqlite3).
- Evoluiu de single-tenant (so Dr. Antonio) pra multi-tenant com 5
  contas + 1 super-admin. Cada tenant tem seu Instagram, prompt,
  agenda, produtos e instructions proprias.
- Integracoes: Instagram Graph API (Meta), Anthropic Claude API,
  autenticacao JWT.
- Deploy: VPS Hostinger (/opt/medbot) com PM2 + Nginx + Let's Encrypt.
- Estado: producao funcionando. Ultima sessao focou em Dr. Francisco
  (tenant novo) e refatorar selecao de modelo Claude por tenant.

2) STACK E ARQUITETURA
================================================================
- Backend: Node.js 22 + Express (ESM). Sem build step.
- Banco: SQLite (better-sqlite3), arquivo data.db. Migracoes

4) ARQUITETURA DE PROMPT (MUDOU MUITO!)
================================================================
ANTES era hardcoded em prompt-builder.js (3 variantes: defaultPrompt,
clinicaPrompt, arrascaetaPrompt). AGORA tudo unificado via DB:

CAMADAS DO PROMPT (rendered em ordem):
  1. system_prompt (instructions.category='system_prompt')
     - markdown completo da persona/regras
     - SOMENTE admin edita via /admin.html -> tab System Prompt
     - cliente NAO ve nem mexe (rota /api/instructions filtra)
  2. Instructions por categoria (cliente edita via /)
     - memoria, convenios, procedimentos, pos_operatorio,
       agendamento, personalizado (+ categorias custom)
     - renderizadas com header natural "## NOME_CATEGORIA"
     - NAO usar header "## ORIENTACOES DO CLIENTE" (LLM trata como menor)
  3. Schedule (estruturado, tabela schedules)
     - rendered como "## AGENDA SEMANAL"
  4. Products (estruturado, tabela products)
     - rendered como "## CATALOGO DE PRODUTOS" agrupado por categoria

INTERPOLACAO em runtime: {phone}, {whatsapp}, {clinic}, {address}, {name}.

CONTEXTO TEMPORAL: data/hora atual em America/Sao_Paulo e injetada
como mensagem do usuario "[Sistema: A data e hora atual e ...]" a cada
chamada (evita o LLM usar datas do historico).

5) MODELOS CLAUDE (REFATORADO NESTA SESSAO)
================================================================
DEFAULTS GLOBAIS (no .env):
  ANTHROPIC_MODEL_PRIMARY=claude-sonnet-4-6
  ANTHROPIC_MODEL_FALLBACK=claude-haiku-4-5-20251001

  (os antigos claude-sonnet-4-20250514 e claude-3-5-haiku-20241022
   foram descontinuados pela Anthropic - resultavam em 404
   not_found_error. Atualizados pra modelos atuais.)

OVERRIDE POR TENANT:
  doctors.model TEXT NULL
  - null = usa global do .env
  - string = sobrescreve (ex.: 'claude-opus-4-7' pra Dr. Francisco)
  - Editavel via admin: /admin.html -> Editar tenant -> tab Dados
    -> dropdown "Modelo Claude (override por tenant)"

CHAMADA: callClaudeReliable(prompt, msgs, {primaryOverride: doctor.model})
em instagram-handler.js e server.js. Implementado dia 26/06/2026.

CASO DE USO: Dr. Francisco tem funil complexo de 8 etapas + 4
memorias + regras restritivas combinadas. Sonnet 4.6 ignora regras
negativas ("nunca repita", "so 1 vez"). Opus 4.7 segue. Cada tenant
individual pode ser ajustado pela margem desejada.

7) FEATURES POR CONVERSA (TENANT PAINEL)
================================================================
Aba "Conversas" no painel tenant tem por conversa:
  - Pausar/Retomar bot (toggle especifico) - bot deixa de responder
    pra esse paciente sem desativar geral
  - Zerar contexto - apaga mensagens da conversa, mantem lead_name
  - Mensagem manual (atendimento humano)

Schema: conversations.bot_paused INTEGER DEFAULT 0
Endpoints: PUT/POST /api/conversations/:id/{pause,clear-context}

instagram-handler.js: verifica bot_paused antes de processar. Se
pausado, salva a msg do usuario no historico mas NAO responde.

9) OTIMIZACOES DE CUSTO (PLANEJADAS, NAO IMPLEMENTADAS)

A) PROMPT CACHING (Anthropic API)

   - TTL 5 min, mantem cache quente entre mensagens
   - Mover contexto temporal pra fora do system block (system precisa
     ser estavel byte-a-byte pro cache hitar)
   - IMPLEMENTACAO: ~15 linhas em instagram-handler.js e server.js

B) MODELO POR TENANT - JA IMPLEMENTADO (commit 226ee79)
   - Sonnet 4.6 default global, Opus override individual no Dr. Francisco

   - Atual: 500. Sanitizer corta em 4 frases / 480 chars mesmo.
   - Trocar pra 350 reduz teto de output cost (5x mais caro/token).

Quando retomar: comecar pela A (caching) que e o maior ganho.

12) COMANDOS DE OPERACAO
================================================================
DEPLOY:
  cd /opt/medbot
  git pull
  pm2 restart medbot

STATUS:
  pm2 list
  pm2 logs medbot --lines 50 --nostream
  curl -s http://localhost:3000/health

DIAGNOSTICOS:
  # Ver instructions de um tenant + render final do prompt
  node scripts/diagnose-instructions.mjs <doctor_id>
  node scripts/diagnose-instructions.mjs <doctor_id> --search <termo>

  # Ver qual modelo respondeu nas ultimas mensagens
  pm2 logs medbot --lines 500 --nostream 2>&1 | awk '
    /attempt_success/ { status="OK " }
    /api_error/ { status="ERR" }
    /model:/ {
      if (status != "") { print status, $0; status="" }
    }' | sort | uniq -c | sort -rn

DB DIRETO (debug):
  node -e "
  import('better-sqlite3').then(m=>{
    const db=new m.default('/opt/medbot/data.db');
    console.table(db.prepare('SELECT id,name,model,bot_active FROM doctors').all());
    db.close();
  });
  "

LIMPAR CONTEXTO DE UMA CONVERSA (escolher pessoa especifica):
  node /opt/medbot/clear-context.mjs <doctor_id> --list
  node /opt/medbot/clear-context.mjs <doctor_id> --clear-sender <sender_id>
